# Как объяснить Drift Sentinel

Запусти воспроизводимый эксперимент и открой report.json. Сначала объясни происхождение данных: они синтетические. Затем покажи три временные границы и строки, чьи метки ещё не известны.

Вопросы:

1. Почему хронологический split сам по себе не устраняет утечку delayed labels?
2. На каких данных обучаются imputer/scaler и выбирается threshold?
3. Что показывает average precision и почему нужна prior baseline?
4. Чем covariate drift отличается от concept drift? Почему PSI не доказывает падение качества?
5. Почему bootstrap по отдельным строкам может быть некорректен для связанных инцидентов?

Практика: измени последние недоступные labels и убедись, что модель и метрики не изменились. Измени распределение одной фичи, сохраняя label relationship, и сравни PSI с качеством. Следующее расширение — группировка по incident_id и block bootstrap с документированным протоколом.

Для позиции DevOps/MLOps важнее воспроизводимость, артефакты, версии и корректные сигналы мониторинга, чем высокий score на синтетике. Не используй эти результаты как обещание качества на реальных инцидентах. Проект создан с AI-помощью; самостоятельно повтори эксперимент и объясни ограничения.
